# AdventureWorks Azure Project

An end-to-end medallion-style data engineering project on the AdventureWorks dataset. Azure Data Factory copies CSV files from GitHub into the bronze layer of Azure Data Lake Storage Gen2 using a metadata-driven pipeline, an Azure Databricks notebook cleans and transforms them into Parquet in the silver layer, and Azure Synapse Analytics (serverless SQL pool) exposes the silver data as `gold` views and materialises it as external tables (CETAS) in the gold layer.

The repository was initialized by Azure Data Factory and also holds the Synapse workspace Git artefacts.

## Architecture / Flow

```text
GitHub (raw.githubusercontent.com, CSV)
   │  ADF pipeline GittoRow: Lookup parameters/git.json -> ForEach -> Copy (HTTP -> ADLS)
   ▼
ADLS Gen2  bronze/<folder>/<file>.csv
   │  Databricks notebook bronze_silver_transformations
   ▼
ADLS Gen2  silver/<entity>/   (Parquet)
   │  Synapse serverless SQL: OPENROWSET views in schema gold
   ▼
ADLS Gen2  gold/ext<entity>/  (Parquet, CREATE EXTERNAL TABLE AS SELECT)
```

## Tech stack

- Azure Data Factory (`df-azureproject-AW`) with ARM template export
- Azure Data Lake Storage Gen2 (`parameters`, `bronze`, `silver`, `gold` containers)
- Azure Databricks / PySpark (Unity Catalog volumes)
- Azure Synapse Analytics serverless SQL pool (database `AdventureWorks`), managed identity credential

## Ingestion: ADF pipeline GittoRow

Defined in `df-azureproject-AW/ARMTemplateForFactory.json`.

1. **LookupGit** reads `parameters/git.json` (dataset `ds_git_parameters`) with all rows returned. Each row supplies `p_rel_url`, `p_sink_folder` and `p_sink_file`.
2. **ForEachTable** iterates the rows sequentially and runs **DynamicCopy**:
   - Source `ds_dynamic_sc`: delimited text over HTTP (`httpLinkService`, base URL `https://raw.githubusercontent.com/`, anonymous) at `p_rel_url`.
   - Sink `ds_dynamic_sink`: delimited text in the `bronze` container at `p_sink_folder/p_sink_file`.

The template also contains two standalone datasets, `ds_http` (a single `AdventureWorks_Products.csv` over HTTP) and `ds_raw` (`bronze/products/products.csv`).

## Transformation: Databricks notebook

`DataBricks/bronze_silver_transformations.ipynb` reads CSVs from `/Volumes/azureproject/dbo/bronze/` and writes Parquet to `/Volumes/azureproject/dbo/silver/` (overwrite mode).

| Entity | Transformation |
| --- | --- |
| Calendar | Adds `month` and `year` from `Date` |
| Customers | Adds `FullName` from `Prefix`, `FirstName`, `LastName` (note: the write cell currently writes the calendar DataFrame to the customers path) |
| Products | `ProductSKU` and `ProductName` truncated to their first token |
| Sales 2015-2017 | Unioned into one DataFrame; `StockDate` cast to timestamp; `S` replaced with `T` in `OrderNumber`; `multiply` = `OrderLineItem * OrderQuantity`; written as `AdventureWorks_Sales` |
| Product categories, subcategories, returns, territories | Written as-is |

It also includes a short analysis cell counting orders per `OrderDate`.

## Serving: Synapse SQL scripts

Run against the serverless (`Built-in`) pool:

| Script | Purpose |
| --- | --- |
| `Create_schema` | `CREATE SCHEMA gold` |
| `Create Views` | `gold` views over each silver Parquet folder using `OPENROWSET` (calendar, customers, product categories, products, returns, sales, territories, subcategories) |
| `AdventureWorks_Customers` | Earlier single-view script over the customers silver folder |
| `Create Conncections` | Master key, database-scoped credential using managed identity, external data sources `source_silver` / `source_gold`, Parquet file format |
| `Create external table` | CETAS: `gold.ext<entity>` tables written to the `gold` container |

## CI/CD

- **Data Factory**: ARM templates were generated by an ADF publish and merged into `main` from the `adf_publish` branch via pull request. `ARMTemplateForFactory.json` can be deployed with its parameters file; the `linkedTemplates` variant expects `containerUri` and `containerSasToken` for a storage location hosting the linked templates.
- **Synapse**: the workspace is Git-integrated with `main` as the publish branch (`publish_config.json`); publishing produced `synapseworkspace-azureproject-aws/TemplateForWorkspace.json`.
- No Azure DevOps or GitHub Actions pipeline definitions are included.

## Prerequisites

- ADLS Gen2 account with `parameters`, `bronze`, `silver` and `gold` containers, and a `parameters/git.json` listing the files to copy
- Databricks workspace with a Unity Catalog volume path `/Volumes/azureproject/dbo/` mapped to the lake
- Synapse workspace with managed identity access to the storage account
- Storage account key supplied as a secure parameter at deployment (left empty in the parameter files)
